# Domain Chief Provider

Use the Domain Chief provider to manage the hosted DNS records, web redirects and mail forwards of domains in [Domain Chief](https://domain.chief.app), and to read your domains.

The provider manages existing domains only, it does not register, transfer or delete domains.

## Example usage

```terraform
terraform {
  required_providers {
    domainchief = {
      source = "chieftools/domainchief"
    }
  }
}

# Configure the token with the DOMAINCHIEF_API_TOKEN environment variable.
provider "domainchief" {}
```

## Authentication

The provider needs a Domain Chief API token. Use a [team access token](https://account.chief.app/team/select/token/create) so the configuration keeps working when people leave the team, and give it only the scopes your configuration needs:

| Resource or data source | Scope |
|---|---|
| `domainchief_dns_record` | `domainchief:dns:write` |
| `domainchief_dns_records` | `domainchief:dns:read` |
| `domainchief_web_redirect` | `domainchief:redirects_web:write` |
| `domainchief_mail_forward` | `domainchief:redirects_mail:write` |
| `domainchief_domain`, `domainchief_domains` | `domainchief:domains:read` |

Set the token with the `DOMAINCHIEF_API_TOKEN` environment variable instead of writing it in your configuration.

A personal access token can manage every team you belong to. Set `team` to the team ID to select the team, otherwise your default team is used.

### Optional

- `api_token` (String, Sensitive) A Domain Chief API token. Use a team access token with only the scopes your configuration needs. Can also be set with the `DOMAINCHIEF_API_TOKEN` environment variable.
- `api_url` (String) The base URL of the Domain Chief API. Defaults to `https://domain.chief.app/api/v1`. Can also be set with the `DOMAINCHIEF_API_URL` environment variable.
- `team` (String) The ID of the team to manage, only needed for tokens that are not scoped to a single team, such as personal access tokens. Can also be set with the `DOMAINCHIEF_TEAM` environment variable.
